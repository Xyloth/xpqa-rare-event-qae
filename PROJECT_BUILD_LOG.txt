# XPRIZE Quantum Apps — Phase I “Phase-1.5” Build Log (Seed → Tickets 1–5)

**Primary application:** satellite conjunction / collision probability estimation under uncertainty
**Quantum hook:** quantum amplitude estimation (QAE) framing for rare-event probability estimation, inserted only in the expensive “refinement slice” (hybrid workflow)
**Goal of this repo:** produce **reviewer-proof classical benchmarking + feasibility evidence** so our Phase I submission looks “execution-ready,” not speculative.

## 0) What we started with (“the seed” before today)

We already had a functioning, reproducible **Tier-1** rare-event benchmark harness with:

* **A simple analytic encounter model** (closest-approach / miss-distance event)
* **Classical baselines**:

  * Plain Monte Carlo (MC)
  * Importance Sampling (IS)
* **Tier calibration** to control “rarity” (Tier 2 / Tier 3 regimes)
* **CI reporting + convergence plots**
* **A basic bench suite** to compare methods across tiers

This seed was enough to show “MC is bad in rare regimes; IS helps,” but it still looked “toy-ish” and not obviously conjunction-ops grounded. It also lacked (a) non-Gaussian uncertainty realism, (b) a second non-strawman rare-event baseline, (c) operationally recognizable encounter-plane framing, and (d) feasibility/resource estimation artifacts.

## 1) Ticket 1 — Realistic uncertainty: Gaussian mixtures + near-threshold “cliff edge” regimes

**What we built**

* **Two-component Gaussian mixture uncertainty** for inputs:

  * Mode A: nominal tight uncertainty
  * Mode B: small weight `w` (e.g., 0.05) with inflated covariance `k` (e.g., 10×) and optional mean shift
    → models “small bad mode dominates tail risk” (realistic non-Gaussian behavior).
* **Near-threshold scenarios** (mean miss distance close to the hard-body threshold `d0`)
  → models “boundary-layer / cliff-edge” regimes where tiny shifts flip event outcomes.

**Why it matters**

* Makes the task **realistic**: tail risk can be dominated by small-probability “wide error” modes.
* Makes the benchmark **hard in a realistic way**: near the decision boundary, confidence is expensive.

**Key artifacts**

* `results/plots/mixture_effects.png` — CI width vs N, showing mixture and near-threshold effects
* `results/mixture_summary.md` — reviewer-safe narrative (zero-hit aware, stress-test labeled)
* Optional diagnostics: `results/plots/is_ess_diagnostics.png`

**Writing implication**

* This powers the “why classical refinement is expensive” story in:

  * **Problem/Impact** (uncertainty, tail risk, decision pressure)
  * **Classical Benchmarking**
  * **Novelty** (model realism + controlled stress regimes)

**What we built**
A new “space-recognizable” model that maps directly to conjunction ops:

* **Encounter-plane uncertainty model (2D)**: sample relative position at TCA in the encounter plane
* Event predicate: **miss distance < d0**
* Supports:

  * single Gaussian and Gaussian mixture
  * near-threshold stress tests

**Why it matters**

## 5) Ticket 5 — Phase II plan evidence: Precision calibration + Telescoping/gating (hybrid insertion)

This ticket is a *massive* maturity signal because it turns Phase II promises into **data-backed levers**.

### 5A) Precision calibration (quantization sweep)

**What we built**

* Signed fixed-point quantization utilities and quantized event evaluation
* Precision sweep across bits = {12,16,20,24,32} comparing Pc error vs float baseline
* Rule: recommend smallest b such that quantization error ≤ 0.25 × estimator CI width (decision-grade)

**Result**

* Baseline regimes recommended **b = 12**
* Near-threshold (stress case) recommended **b = 16** (Ticket 5.1 robustness check)

**Key artifacts**

* `results/tables/precision_sweep.csv`
* `results/plots/precision_error_vs_bits.png`
* `results/plots/precision_ciwidth_vs_bits.png`
* `results/precision_sweep_summary.md`

**Writing implication**

* This directly reduces FT resources by justifying **lower precision** than naive 32-bit.
* It turns QDK “big qubits” into a concrete Phase II lever:

  * “we will calibrate precision to decision needs, then re-estimate resources.”

### 5B) Telescoping / gating simulation (hybrid pipeline)

**What we built**

* A scenario population simulation (K=2000)
* A cheap prescreen (coarse estimate + conservative margin)
* Classifies scenarios into:

  * SAFE / DANGER / GRAY
* Runs refinement only for GRAY using a strong baseline method (IS)

**Result (default policy run)**

* SAFE ≈ 53.1%
* DANGER ≈ 36.8%
* GRAY ≈ 10.1%
* Expected compute reduced ~88% vs “always refine” proxy

**Key artifacts**

* `results/tables/gating_simulation.csv`
* `results/plots/gating_fraction_vs_policy.png`
* `results/plots/gating_compute_hist.png`
* `results/plots/gating_expected_compute.png`
* `results/gating_summary.md`

**Writing implication**

* This justifies the hybrid strategy:

  * “Quantum is only used in the GRAY refinement slice”
* It supports:

  * Impact (faster decisions, fewer unnecessary refinements)
  * Viability (quantum use is sparse, not constant)
