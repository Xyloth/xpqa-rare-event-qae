# XPRIZE Quantum Applications — Rare-Event Probability Estimation for Conjunction Risk

This repository contains the technical work supporting an **XPRIZE Quantum Applications Phase I Wild Card** submission focused on **rare-event collision probability** estimation for space conjunction assessment.

The core task is estimating:

\[
P_c = \mathbb{P}(d_\mathrm{miss} < d_0)
\]

under uncertainty—especially in **tail / decision-boundary regimes** where classical refinement becomes expensive. We benchmark multiple **best-practice classical baselines** (Monte Carlo, Importance Sampling, and Subset Simulation / Splitting), stress-test realism with **non-Gaussian mixture uncertainty** and **near-threshold “cliff edge” cases**, and provide **fault-tolerant resource estimation** artifacts for an oracle-arithmetic skeleton.

A curated set of “paper figures” is tracked under `paper/figures/` for quick review.

---

## What’s in here (at a glance)

### Models
- **Encounter-plane model (2D):** uncertainty in relative position at time of closest approach, with an event predicate
  \(x^2 + y^2 < d_0^2\) (oracle-friendly; avoids reversible square roots).
- Scenario variants:
  - `baseline_single` (single Gaussian)
  - `baseline_mixture` (Gaussian mixture “wide error mode”)
  - `near_single` (decision-boundary stress test)
  - `near_mixture` (stress test + mixture)

### Classical baselines (benchmark bar)
- **MC:** plain Monte Carlo with replicate-based confidence intervals.
- **IS:** importance sampling with diagnostics (ESS where applicable).
- **SPLIT:** subset simulation / splitting for rare-event estimation.

### Phase II plan evidence (measured)
- **Precision calibration:** quantization error vs fixed-point bits (includes near-threshold robustness).
- **Telescoping / gating:** a toy screening pipeline showing refinement concentrates in a small “gray zone,” motivating targeted use of expensive methods (and targeted use of quantum).

### Viability / resources
- **Parametric scaling model** (oracle cost + AE-vs-MC scaling plots).
- **Microsoft QDK Resource Estimator sweep** for an oracle-arithmetic skeleton (scope and caveats included).

## Quickstart (reproduce the judge-facing figures)

From repo root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
pip install -r requirements.txt
```

### 1) Encounter-plane paper figures (replicate-based CIs)
```bash
python scripts/run_encounterplane_replicates.py
python scripts/plot_encounterplane_paper_figures.py
```

### 2) Compute-normalized classical benchmark plot (MC / IS / SPLIT)
```bash
python scripts/run_splitting_suite.py
python scripts/plot_ciwidth_vs_compute.py
```

### 3) Viability / resource artifacts (parametric model)
```bash
python scripts/generate_resource_estimate.py
```

### 4) Microsoft QDK Resource Estimator sweep (oracle arithmetic skeleton)
```bash
python scripts/run_qdk_resource_estimate.py --bits 16,24,32 --error_budgets 1e-2,1e-3,1e-4
```

### 5) Phase II plan evidence (gating + precision)
```bash
python scripts/run_gating_simulation.py
python scripts/plot_gating_results.py
python scripts/run_precision_sweep.py
python scripts/plot_precision_sweep.py
```

## How this maps to the Phase I narrative (A–I)

- **A. Problem statement & scope:** encounter-plane conjunction probability estimation with a miss-distance event predicate.
- **B. Impact:** tail refinement is expensive; screening/gating shows refinement concentrates in a small subset of cases.
- **C. Quantum advantage (hypothesis):** amplitude estimation improves scaling in oracle calls (≈ \(1/\epsilon\)) vs naive MC (≈ \(1/\epsilon^2\))—but only if oracle + state prep costs are engineered down.
- **D. Classical benchmarking:** MC vs IS vs SPLIT across baseline, mixture, and near-threshold regimes (compute-normalized).
- **E. Viability:** explicit oracle decomposition (squared norm compare), conservative scaling model, and third-party estimator output (QDK) for magnitude checks.
- **F. Novelty:** hybrid refinement insertion + oracle feasibility framing + measured Phase II levers (precision + gating), not “we invented Pc.”
- **G/H. Evidence:** all figures/tables are generated by scripts; paper figures are copied into `paper/figures/`.
- **I. References:** competition docs + rare-event estimation literature + QDK estimator docs (see narrative PDF).

## Notes on scope and honesty (important)

We **do not** claim that today’s NISQ devices can run this end-to-end. We provide:
- strong classical benchmarks and stress tests,
- a clean oracle definition,
- and realistic fault-tolerant feasibility artifacts.

### Why the QDK resource estimate omits state preparation and the full AE loop
The QDK sweep is intentionally scoped to a **representative oracle arithmetic skeleton** (compute \(x^2+y^2\), compare to \(d_0^2\), mark, uncompute). We omit:
- **state preparation** (loading Gaussian/mixture uncertainty), and
- the **full amplitude-estimation control structure**,

because those pieces are highly design-dependent and are a major focus of Phase II engineering (where we will iterate oracle/state-prep designs and re-run estimator-backed resource estimates at calibrated precision). We still account for AE scaling and discuss how end-to-end costs scale with \(\epsilon\).
